# Footer feedback implementation plan

Goal: visitors can privately report a bug, share feedback, or suggest a component without an account, in the existing Keeby-inspired theme.

Architecture: a small client form in the footer sends multipart data to a Supabase Edge Function. Turnstile verifies visitors; a service-only SQL function atomically enforces limits and saves a private inbox record. Optional PNG/JPEG/WebP screenshots live in a private bucket. Resend sends a notification to the owner's configured Gmail address. No client secrets or new runtime dependency.

Design: inline two-column card on desktop, stacked at 390px; native radio choices styled as keys, labeled message/email/file inputs, explicit pending/error/success states, and a footer Feedback anchor. Until configured, show a GitHub issue fallback and never report a fake success. Email and screenshot are optional. Page path excludes query/hash. No account required.

Approaches considered: GitHub-only is simple but needs an account; direct email exposes the address and loses structured tracking. Private Supabase intake with optional email alerts follows the design approved in conversation. Resend and Turnstile are implementation choices; owner configures secrets. No production deployment in this PR.

Tasks:
1. Test input limits, content sniffing, private access and atomic quotas with tsx/PGlite; implement shared validation and migration.
2. Implement injectable Edge handler; test CAPTCHA failure, oversized streaming bodies, origin rejection, storage/email failures and success with fake external services. Keep Deno bootstrap separate.
3. Add footer form and lazy CAPTCHA; update CSP only for Cloudflare challenge resources. Preserve 44px targets and theme tokens.
4. Document migration, function, CAPTCHA, email setup, inbox access and retention. Run all four required commands and browser-check mobile/desktop before PR.

Review focus: no direct anonymous database/storage access; fail closed on missing CAPTCHA config; global quota even if network identity changes; saved submissions remain successful if notification delivery fails; no lost form text on errors. Real CAPTCHA/email delivery requires owner credentials and a post-setup smoke test.
